xPiZzAxAnimation 1.0.3 — Fabric 1.20.4 / Java 17

Исправлено в этой версии:
- Поведение рук возвращено к реализации из 1.0.1: специальная подмена правой
  руки ванильной позой при приседе/поглаживании из 1.0.2 удалена. Отдельный
  фикс поглаживания питомцев в этой версии не заявляется.
- Вспомогательные проверки, отчёты аудита, CSV и старые патчи исключены из
  архива исходников; ресурсы и код, необходимые для сборки, сохранены.
- Пояс с инструментами из RP 1.43.3 (золотая конская броня, CMD 824) крепится
  отдельно на линию талии, а не использует смещение предмета в левой руке.
- Для изгиба рук и туловища повторно используются математические объекты,
  чтобы не создавать временные векторы/кватернионы при каждом рендере.

Сохранённые оптимизации из RPM Roleplay 1.0.15:
- В рендере машин проверка класса выполняется один раз на класс, а не через
  создание строки и перевод регистра на каждом кадре для каждой сущности.
- Повороты машин используют повторно используемый Quaternion вместо двух новых
  объектов при ускорении/заносе каждого кадра. Кэш скоростей использует слабые
  ссылки на сущности и не накапливает старые UUID после закрытия Replay/мира.
- Проверка ReplayMod при рендере игрока использует уже имеющийся безопасный
  ReplayState, без повторной reflection-инвокации для каждого игрока.
- EmoteCraft API вызывается через заранее подготовленный MethodHandle, если
  EmoteCraft установлен; при его отсутствии optional-класс не загружается.
- Классификация предмета в offhand переиспользуется в течение рендера игрока
  для feature/held-item проходов вместо повторного анализа одной модели.
- Когда ночное зрение Replay выключено и его эффект не принадлежит моду,
  render-hook немедленно выходит, не опрашивая состояние Replay каждый кадр.
- Динамические цвета градиентов темы считаются один раз на backdrop-кадр,
  а не заново при каждом элементе меню. Внешний вид и анимация меню сохранены.
- Превью глаз больше не создаёт временные записи IdentityHashMap при каждом
  кадре: скрытие/восстановление частей модели использует повторно применяемый
  стек, сохраняя тот же внешний вид.

Новое в 1.0.14 — оптимизация FPS:
- Убран полный проход по кэшу всех до 1024 игроков на каждом игровом тике.
  Анимация обновляет только локального игрока и недавно отрисованных сущностей;
  очистка устаревших записей выполняется периодически.
- Классификация предмета на спине вычисляется один раз за рендер игрока.
  Контексты подавления дубликатов переиспользуются вместо создания объектов
  каждый кадр. Логика EmoteCraft и сама точка крепления не изменены.
- В меню карточки показывают лёгкий превью-рендер кожи/анимации/глаз без
  дополнительных слоёв брони, плащей и предметов.
- Удалены повторные вычисления цветов HSV и создание временных списков/массивов
  каждый кадр палитры; фаза анимированного градиента вычисляется один раз за кадр.
- Переиспользуются JOML-объекты для двух предпросмотров вместо новых объектов
  при каждом вызове отрисовки.

Сборка этой версии в данной среде не выполнена: Wrapper требует Gradle 8.12.1,
но сеть недоступна. Это исходный проект для сборки, не готовый JAR.

Новое в 1.0.13:
Исправлено дублирование предметов, которые RPM переносит из левой руки
на спину, во время танцев EmoteCraft. Раньше RPM отключал собственный
VanillaEmoticonsBridge на время EmoteCraft, а проверка подавления копии
в руке зависела от наличия RPM-позы. Теперь оригинальный рендер offhand
подавляется в рамках рендера игрока независимо от того, кто управляет
анимацией тела. Рендер аксессуара на спине остаётся разрешённым.
Правило применяется ко всем предметам, которые классификатор RPM
определяет как BODY, а не только к косам или конкретным ID.

Сборка этой версии в данной среде не выполнена: Gradle Wrapper требует
загрузить Gradle 8.12.1, но доступ к services.gradle.org отсутствует.
Это обновлённый исходный проект, а не готовый RPMRoleplay.jar.

RPM Roleplay 1.0.11 — Fabric 1.20.4 / Java 17

Новое в 1.0.11:
При резкой смене движения вперёд/назад шаг сразу меняет направление,
сохраняя текущую фазу. Убрано торможение часов клипа через нулевую
скорость: оно давало паузу при W → S и особенно при частых W/S.
Обратная ходьба сохранена, направление по-прежнему определяется
перемещением относительно туловища, а не клавишами или камерой.

От первого лица с модом на вид тела используемая для еды/питья рука
сохраняет исходную позу относительно камеры. Наклон нашего туловища
больше не уводит её к скрытой анимированной голове за краем экрана.
Работает для физической левой/правой руки и левшей, по UseAction EAT/DRINK.
Остальное тело и свободная рука продолжают анимацию. Вид на F5,
другие игроки, Replay и подзорная труба сохраняют прежнюю позу.
FirstPerson и NEA остаются необязательными. Зонты не менялись.

Сохранено из 1.0.10:
Зонты возвращены к поведению 1.0.8: рука с зонтом снова следует нашей
анимации. Правило ванильной позы руки с зонтом из 1.0.9 удалено.
Еда, питьё и подзорная труба сохраняют свой прежний отдельный фикс.

Сохранено из 1.0.9:
При движении назад циклы ходьбы, спринта и приседания проигрываются
в обратном направлении. Направление определяется по перемещению и
повороту туловища; работают другие игроки и записанные в Replay движения.
При смене направления фаза шага не сбрасывается. Idle, падение,
прыжок и другие отдельные действия продолжаются обычным образом.
Ресурс-пак не изменён. Еда/питьё/подзорная труба, прежние крепления,
Replay груди/машин, глаза, меню и необязательные интеграции сохранены.

Сохранено из 1.0.8:
При частых W/A/S/D переходы между стоянием, ходьбой, спринтом и
приседанием сохраняют всю текущую смесь поз. Новый переход не подменяет
её необработанным предыдущим клипом; повторное движение продолжает фазу
шага, а не сбрасывает её в начало. Смешивание интерполируется между
игровыми тиками и не зависит от первого лица/F5/свободной камеры.
Повторные настоящие прыжки по-прежнему запускают отдельный клип прыжка.
Туловище от первого лица возвращено к прежней полной анимации:
фильтр корня/талии и восстановление ванильного торса из 1.0.7 больше
не применяются.

Сохранены из 1.0.7: состояние своего игрока обновляется на игровом тике
даже при скрытом теле и не удаляется по тайм-ауту видимости; наведение
кнопок отделено от фокуса мыши после клика; выключенные карточки имеют
серую волну и наведение; дополнительные моды остаются необязательными.
Обычная пауза одиночного мира по-прежнему останавливает игровые тики.

Установка: положи xPiZzAxAnimation.jar в папку mods. Перед запуском удали
старые RPMRoleplay.jar и xPiZzAxMod / xPiZzAxMod-NoMusic, чтобы не запускать
две версии анимаций одновременно.
Fabric API обязателен. ReplayMod и Cars необязательны. Player Animator и Bendy
включены внутрь JAR. Для груди нужен исходный rpmclient
7.1; для анимированных глаз — существующие EMF/ETF и подходящий скин.
Музыкального кода, Spotify, JNA и веб-расширения в этой версии нет.
FirstPerson, Not Enough Animations, EMF/ETF, Emotecraft, Gender Mod,
RPM-клиент, Cars и ReplayMod не обязательны для запуска xPiZzAxAnimation.
Интеграции включаются при наличии соответствующего мода. Дополнительные
проверки классов не дают подключить отсутствующий FirstPerson/NEA/Gender
hook. Возможности внешнего мода требуют установки самого внешнего мода.

K — меню анимации и глаз: две увеличенные карточки без заголовка и логотипа.
Нажатие на 3D-модель включает/выключает анимацию тела, на голову — глаза.
Управление независимое, оба состояния сохраняются после перезапуска.
Цветная рамка плавно гаснет до серой при выключении; превью следуют за
курсором. Нет отдельных кнопок Vanilla/Off. Также работают Tab и Enter/пробел.
Карандаш открывает выдвижную персонализацию: палитра, оттенок, HEX/RGB и
готовые цвета. Превью при открытии приглушаются, клики не проходят сквозь
палитру. На широком окне палитра располагается рядом, на узком — поверх.
Цвет меняется сразу и общий для этого меню и WEATHER CONTROL.
В меню погоды отдельного карандаша нет. Esc сначала закрывает палитру,
повторное нажатие — само меню.
Цвет и переключатели хранятся в config/rpmmodels.properties, вне JAR.
Настройки сохраняются в config/rpmmodels.properties. Ключи настроек и старые
внутренние имена rpmmodels оставлены для совместимости. Fabric mod ID и имя
JAR теперь xpizzaxanimation / xPiZzAxAnimation. UpdaterX остаётся отдельным
клиентским модом; в этот исходник его JAR и его зависимости не копируются. При движении ползунка
цвет меняется в памяти; запись выполняется после отпускания мыши/закрытия,
а не каждый кадр. Градиенты и свечение работают только в открытом меню.
G — WEATHER CONTROL: время, погода и свет в Replay. Shift+G — быстрый день.
Эта клавиша и Replay-функции доступны только с установленным ReplayMod.
Без него остаются анимация, глаза, обычная грудь RPM и физика транспорта;
запись/воспроизведение груди и машин включаются вместе с ReplayMod.
Исходные моды rpmclient/Cars по-прежнему нужны для их собственных функций.
Категория клавиш: xPiZzAxAnimation. При первом запуске анимация включена;
затем восстанавливается выбранное состояние. Сохраняются ограничения для полёта на
элитрах, воды, лестниц, транспорта и несовместимых действий с оружием.

Грудь RPM записывается в xpizzax/rpm_gender_v1.json внутри .mcpr.
Форматы 1/2 читаются, новые записи используют формат 3. Пакеты профиля
RPM фиксируют явное включение/отключение, даже если игрок вне экрана.
Очистка live-кэша RPM сама по себе не превращается в записанный Male.
Восстановление идёт по UUID и времени самой записи, независимо от текущего
live-кэша RPM. Перемотка, пауза и повторное открытие используют записанные
значения. Male/отсутствие груди остаётся отдельным записанным состоянием.
В старых записях с параметрами, но без физики, размер пружин сразу
инициализируется из записанного размера: ждать live-тиков не требуется.
Если в старой записи нет профиля, но он виден из live-кэша при открытии,
мод запоминает именно этот видимый профиль и сохраняет в .mcpr при
обычном выходе из Replay. Уже записанный Male этим не заменяется.
Если нет ни записанных данных, ни видимого live-профиля, нужна новая
запись с установленным модом.
Исходный RPM-клиент, сервер и его аккаунты мод не изменяет.

Сохранены фиксы крепления ножей/предметов/одежды, Replay транспорта,
скрытие транспортных стоек, камеры, дождя и освещения. При еде и питье
голова сохраняет компенсацию изгиба, а используемая рука следует за ней,
как в существующем исправлении подзорной трубы.
Для предметов анализируются модель, унаследованные геометрия и display,
а не только ванильный ID или наличие CustomModelData. Железный топор в
RPM-паке следует за левой рукой; ножи, часы, зонты, камера и мушкет также
используют руку. Модели, размещённые паком на спине, следуют за туловищем.
Фотографии (filled_map с любым ID/названием) при рендере Not Enough Animations
получают сгиб предплечья в обеих руках, сохраняя его исходное расположение.
Если фото находится именно в левой физической руке, от первого лица
скрывается дополнительная модель тела FirstPerson: остаётся обычная рука
с фото, даже при взгляде вниз с динамическими руками FirstPerson.
Это не выключает анимацию и не меняет сохранённую настройку.
Правое фото само по себе, F5, другие игроки и превью остаются видимыми.
При убирании левого фото тело снова видно. Пустая карта — обычный предмет.
Not Enough Animations и FirstPerson не становятся зависимостями мода.
1.0.5: устранён StackOverflowError при совместной работе с TaCZ/FirstPerson.
Повторный вызов проверки камеры не входит в обработчик фото ещё раз;
без фото слева проверка камеры вообще не нужна.
Ресурс-пак не изменён. После F3+T классификация пересчитывается; сохраняются
только компактные сведения в ограниченных кэшах, не вся геометрия.
Replay-время читается один раз на кадр; незаметные кэшированные NPC не
просчитывают все каналы анимации каждый тик. Кэши имеют прежние пределы,
не очищаются целиком каждый кадр. Профили Replay читаются один раз на
файл; постоянного файлового или сетевого опроса на каждом кадре нет.

Сборка: открой папку в IntelliJ IDEA с JDK 17 или запусти BUILD.bat.
Результат: build/libs/xPiZzAxAnimation.jar. Кэш Gradle и папки build не включены.
Для dev-запуска без ReplayMod: gradlew runClient -PwithoutReplay.
libs/replaymod нужен для компиляции исходника; в готовый JAR он не входит.

Некоторые внутренние имена xpizzax сохранены для совместимости ресурсов
и формата уже записанных Replay. Название мода — xPiZzAxAnimation;
меню погоды — WEATHER CONTROL; меню переключателей без шапки.
